# File Change Monitoring

Baboon reads a tag once and edits it in memory. When a tag you have open is
changed outside Baboon (replaced in File Explorer, regenerated by Tool,
saved by another editor), Baboon notices and reads it again, so a later
Save does not quietly roll the file back.

## When Baboon checks

A loose editing kit watches its tags folder for changes, using the
operating system's file notifications. Moments after something under the
folder changes (about a third of a second after the last write, so a tool
writing in bursts is checked once), Baboon checks its open tags. This works
while Baboon stays in front, for example with Tool or a script running
beside it.

The same notifications keep the tag browser current: a tag created,
deleted or renamed outside Baboon appears or disappears within about a
second. A rescan of a large kit takes a few seconds (about 3 for H3EK's
57,000 tags, in the background), so while something keeps writing, such as
a long Tool batch, rescans are spaced at least 5 seconds apart. Baboon's own
saves don't set one off: the save already updates the browser.

Without a watch the browser rescans the folder every 30 seconds; with one
that has reported something in the last 5 minutes, only every 5 minutes,
as a backstop. The OS can drop notifications when a lot changes at once
(a large Git checkout). Baboon then treats anything as possibly changed:
it checks every open tag, rescans the browser and reloads every Model
Preview. Windows can also stop a watch after such an error without saying
so. That's why a watch that has gone quiet gets the 30-second rescan again.
A watch is restarted if a rescan finds a change it never reported.

An open **Model Preview** reloads when a tag it was drawn from (a shader,
a bitmap, its render model) is saved in Baboon or changes on disk, so
saving a shader in one tab updates the model using it in another. See
[Model Preview](model-preview.md).

An open **Git Review** tab follows along too. A change in the tags folder,
or Baboon regaining focus (say, after committing or pulling in GitHub
Desktop, which changes Git's records but no tags), refreshes it quietly,
with no "Reading Git…" line. It keeps the selected commit and file, and it
waits for a diff you just clicked to finish loading first. Changes inside
a `.git` folder are ignored, so a repository kept inside the tags folder
does not set off a refresh every time Git Review reads it.

Open tags are also checked whenever Baboon's window regains focus, in case
a notification was missed or the folder could not be watched. Model
Previews are rechecked on focus too, unless the watch has reported
something lately. Both checks run in the background.

A file counts as changed when it differs from what Baboon loaded or last
saved, not when it is merely newer. A copy made in File Explorer keeps the
original's modified date, so a replacement can look older than the tag it
replaced and is still noticed. A file whose date changed but whose contents
did not is left alone. Baboon's own saves are never mistaken for outside
changes.

Save also looks at the file once more just before writing. If it changed
since you opened the tag (say, while Baboon stayed in front), and you have
not already chosen Keep My Edits for that version, nothing is written and a
**Tag Changed on Disk** window asks what to do:

- **Keep My Edits and Save** replaces the file with your version. If you
  were closing tabs or quitting, that carries on once nothing is left
  unsaved.
- **Reload from Disk** discards your edits and loads the file.

Save on a tag with no unsaved edits stops the same way. The window then
offers **Save Anyway**, which writes the version open in Baboon over the
file.
- **Cancel** saves nothing. The banner below stays on the tag, so the
  choice is still waiting.

A file deleted in the meantime is simply written back.

Tags in containers, packages and monolithic caches are not checked.

## What happens

- **A tag with no unsaved edits** is read again from disk. The status bar
  says so ("Reloaded warthog.model: changed on disk"), and open previews
  refresh with it. Its undo history starts again from the reloaded version,
  so Undo cannot bring back what the file no longer holds.
- **A tag with unsaved edits** keeps them, and an amber banner appears
  under its header: "brute.model changed on disk. You have unsaved edits."
  It waits on a background tab until you open it, and editing carries on
  while it shows. The fields move down to make room, but stay scrolled
  where they were.
  - **Reload from Disk** discards your edits and loads the file as it is
    now.
  - **Keep My Edits** dismisses the banner and keeps your version. Baboon
    trusts that choice: your next Save replaces the file without asking.
    If the file changes again afterwards, the banner comes back.
  - Saving while the banner shows does not write: the Tag Changed on
    Disk window asks you to choose first.
- **A tag whose file was deleted** (or moved away) stays open as it was,
  with a red banner: "brute.model was deleted from disk." The tab's dot
  turns red, whether or not the tag has unsaved edits, and the tag leaves
  the browser.
  - **Save** writes the tag back where it was, recreating its folder if
    needed, and it returns to the browser.
  - **Close Tab** closes it, asking first if it has unsaved edits, since
    they are the only copy left.
  - If the file comes back on its own (restored in Explorer or by Git),
    the banner goes at the next check.
